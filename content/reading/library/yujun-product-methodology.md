## Products are exchanges, not feature lists

Yu Jun frames product management around the relationship between users, firms, and products. The publisher’s outline moves from those relationships to transaction models and decision-making. The useful shift is to ask what value changes hands, not simply what the team can ship. A user can like an idea and still have no reason to leave an existing solution.

## Make the alternative visible

A practical application is to write down the current workaround before evaluating the new experience. What does the user already get? What effort, risk, trust, or learning would switching require? This exercise is an application of the book’s exchange-centered framing, not a formula that guarantees adoption. Different users can face very different tradeoffs even when they see the same interface.

## Turn the model into a test

Choose one concrete user situation. Describe the existing behavior, the proposed benefit, and the cost of changing. Then observe whether the user actually makes the exchange. Keep the firm’s ability to sustain the service in view as well: a product must create value for the user without making continued provision impossible. Treat the model as something to revise with evidence, not a way to make intuition sound scientific.
